# 画像の名前変更

ImageFixedViewでユーザー画像のプレビューを開き、「名前を変更」から保存ファイル名を変更できる。拡張子は維持し、プリセット画像は対象外。同名の別画像がある場合はエラーにし、上書きしない。

## 参照の追従

- アプリ背景の `settings.json / bgimage.path` とTauri Storeのキャッシュ。
- 作品表紙の `story_metadata.json / cover`。
- Character、World、EntityのJSONの `imagePaths`。
- Aliveの全世代の基準文書・差分、およびNecropolisの資料スナップショット。
- 開いた作品、未保存の資料編集、設定・表紙・画像選択のドラフト、画像一覧・プレビュー。

バックアップは原本の各リビジョンを順に再生して画像フィールドを変更し、新しい差分を生成する。再生結果、世代数、時刻が元の履歴と整合することを確認してから保存する。文章中のパス文字列や本文、資料のUUIDは変更しない。

## 書き込みの順序と旧パス

フロントの `imageReferenceWrites.js` が名前変更、画像操作、JSON保存、表紙・設定保存の順序をそろえる。JSON保存は待機後の最新のドラフトを使用する。バックエンドでも `CONTENT_WRITE_LOCK` を共有して、参照更新と他の文書・バックアップ更新が割り込まないようにする。

`Image/.renames.json` に旧パスから現在のパスへの対応を保存する。遅れて届いた旧パスでの保存は新しいパスへ読み替える。開いている未保存データは必要な画像フィールドだけを更新し、編集中・保存済みの状態を維持する。未完成のJSON文字列は書き換えず、後でJSONとして保存される際に参照を正規化する。

名前変更に使ったパスを別画像へ割り当てると旧参照が別の画像を示すため、履歴のある名前は予約する。追加時にその名前が空いていても、必要に応じてUUIDを付けた別名で保存する。同じ画像を元の名前へ戻す変更は可能。

## トランザクションと回復

1. 名前、衝突、参照先のJSON、旧名の予約を検証する。走査できない対象があれば変更を行わない。
2. `Image/.rename-transaction` に画像と変更対象の原本・変更後データを保存し、同期済みの作業記録を作る。
3. 画像を一時位置経由で移動し、参照ファイルを1ファイルずつ原子的に更新する。移動先を上書きしないWindows APIを使う。
4. 設定キャッシュを読み直し、作業記録を完了状態にする。その後、一時データを片付ける。

途中失敗では記録から元の名前と参照ファイルを復元する。処理途中でアプリが終了した場合は、次回の画像初期化時に未完了の操作を巻き戻す。完了状態の記録が残っていた場合は、結果を維持して一時データだけを片付ける。

復元対象が外部から変更されていた場合は、その変更を無条件に上書きせず、回復記録を残してエラーにする。回復が未完了のときは後続の参照書き込みを止め、再起動時の回復前にさらにデータが変わることを防ぐ。この保護はアプリの処理失敗・終了への対策であり、ストレージ自体の故障に対するバックアップではない。

## IPC

- `plan_user_image_rename({ imgName, newName })`: 検証と保存済み参照の調査。変更は行わない。
- `rename_user_image({ imgName, newName })`: 参照更新を含む名前変更。結果は `old_path`、`new_path`、`redirects`。
- `get_image_renames()`: 起動時に旧パスの対応表を取得。

`newName` は拡張子を含むファイル名。画面では拡張子を除く部分を編集し、送信時に元の拡張子を付ける。

## 検証

Rustのテストは一時ディレクトリ上で、背景・表紙・3種類の資料・バックアップ・削除済み資料、全書き込み境界での失敗、処理途中／完了直後の終了、名前の衝突、大文字小文字だけの変更、連続変更・元の名前への復帰、設定キャッシュ更新失敗を検証する。JavaScriptのテストは未保存ドラフトの保持、保存キューの順序、画面の確認・キャンセル・拡張子維持を検証する。実ユーザーデータの画像をテストのために変更することはない。
